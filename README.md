# control-test

Веб-сервис для проведения тестирования студентов по Wi-Fi в аудитории.
Преподаватель загружает тест в формате GIFT, задаёт количество студентов,
дожидается подключения всех устройств и запускает тестирование —
вопросы транслируются на телефоны студентов синхронно, по одному за раз.

## Возможности

- **Страница студента** (`/`) — ввод имени, подключение к сервису по WebSocket.
- **Страница преподавателя** (`/teacher`):
  - загрузка теста в формате GIFT прямо из браузера;
  - ввод ожидаемого количества студентов в аудитории;
  - счётчик подключённых студентов в реальном времени;
  - кнопка "Начать тест" активируется только когда подключились все
    заявленные студенты (либо запуск принудительно, если часть
    студентов не смогла подключиться);
  - постраничная выдача вопросов — следующий вопрос показывается всем
    студентам одновременно по нажатию кнопки;
  - таблица результатов с числом отвеченных и правильных ответов по
    каждому студенту.
- **Страница теста** (`/test`) — студент видит текущий вопрос и
  отправляет ответ; поддерживаются вопросы с одним правильным ответом,
  с несколькими правильными ответами, верно/неверно и короткий текстовый
  ответ.

## Архитектура

```
Телефон студента ──┐
                    ├──> Nginx (:80) ──> Uvicorn (127.0.0.1:8000, 1 процесс)
Преподаватель ──────┘         FastAPI: /, /teacher, /test,
                               /ws/student, /ws/teacher,
                               /api/upload_test, /api/results
```

Состояние сервиса (список подключённых студентов, загруженный тест,
текущий вопрос, ответы) хранится **в памяти одного процесса**. Это
осознанное упрощение для разового сеанса тестирования — не требует
внешней базы данных или Redis.

**Важно:** сервис нужно запускать строго одним процессом Uvicorn, без
`gunicorn -w N` с несколькими воркерами. При нескольких процессах
каждый будет видеть только часть WebSocket-соединений, и счётчик
подключённых студентов будет считаться неверно.

Раздача Wi-Fi (точка доступа для 150+ студентов) реализуется отдельно
от этого сервиса — например, через Ruckus ZoneFlex H500, подключённую
к ноутбуку по Ethernet. Ноутбук выступает только веб-сервером в этой
локальной сети.

## Требования

- Debian (или другой Linux-дистрибутив) на ноутбуке-сервере.
- Python 3.10+ (используются современные аннотации типов вроде `X | None`).
- Nginx (для production-развёртывания).
- Точка доступа Wi-Fi, подключённая к ноутбуку по Ethernet и
  раздающая адреса в той же подсети (настраивается отдельно от этого
  сервиса).

## Установка

```bash
cd ~/git/control-test
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

## Запуск для разработки

```bash
source venv/bin/activate
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

Откройте:

- `http://<IP-ноутбука>:8000/` — со студенческого телефона.
- `http://<IP-ноутбука>:8000/teacher` — с компьютера или телефона преподавателя.

Узнать IP ноутбука в локальной сети:

```bash
ip addr show | grep "inet "
```

Проверка работоспособности:

```bash
curl http://127.0.0.1:8000/healthz
# {"status":"ok","connected":0,"expected":0}
```

## Запуск в production (systemd + Nginx)

1. Скопируйте юнит systemd и настройте автозапуск:

   ```bash
   sudo cp deploy/testapp.service /etc/systemd/system/
   sudo systemctl daemon-reload
   sudo systemctl enable --now testapp
   sudo systemctl status testapp
   ```

2. Подключите конфиг Nginx:

   ```bash
   sudo ln -sf ~/git/control-test/deploy/nginx_testapp.conf /etc/nginx/sites-enabled/testapp
   sudo rm -f /etc/nginx/sites-enabled/default
   sudo nginx -t
   sudo systemctl reload nginx
   ```

3. Сервис станет доступен на порту 80:
   `http://<IP-ноутбука>/` и `http://<IP-ноутбука>/teacher`.

**Примечание:** пути в `deploy/testapp.service` и
`deploy/nginx_testapp.conf` по умолчанию рассчитаны на пользователя
`aaf` и путь `/home/aaf/git/control-test`. Если у вас другой
пользователь или путь — поправьте оба файла перед копированием
(`User=`, `Group=`, `WorkingDirectory=`, `ExecStart=` в
`testapp.service`; `alias` в `nginx_testapp.conf`).

Конфиг Nginx уже настроен на проксирование WebSocket с увеличенными
таймаутами (`proxy_read_timeout 3600s`), чтобы соединение не
разрывалось во время ожидания подключения всех студентов.

Логи сервиса:

```bash
journalctl -u testapp -f
```

## Формат теста (GIFT)

Сервис поддерживает упрощённую версию формата
[GIFT](https://docs.moodle.org/en/GIFT_format), используемого в Moodle.
Каждый вопрос отделяется от следующего пустой строкой.

**Вопрос с одним правильным ответом:**

```
::Название:: Столица России?
{
=Москва
~Санкт-Петербург
~Новосибирск
}
```

**Вопрос с несколькими правильными ответами** (студент должен отметить
все `=`-варианты, чтобы ответ засчитался верным):

```
::Название:: Какие из этих чисел простые?
{
~1
=2
=3
~4
}
```

**Верно/неверно:**

```
::Название:: Python — компилируемый язык.
{FALSE}
```

**Короткий текстовый ответ** (без `~`, единственный вариант с `=`):

```
::Название:: Сколько будет 2+2?
{=4}
```

Строки, начинающиеся с `//`, считаются комментариями и игнорируются
парсером. Название вопроса (`::Название::`) необязательно — если не
указано, используется начало текста вопроса.

Готовый пример теста лежит в файле `example.gift` — можно сразу
загрузить его на странице `/teacher` для проверки работы сервиса.

## Сценарий использования

1. Преподаватель открывает `/teacher`, загружает файл теста в формате
   GIFT через раздел "Тест (формат GIFT)".
2. Преподаватель вводит количество студентов в аудитории и нажимает
   "Задать".
3. Студенты по очереди подключаются к Wi-Fi точке доступа и открывают
   `/` на телефоне, вводят своё имя.
4. На панели преподавателя счётчик "X / Y подключено" растёт в
   реальном времени; кнопка "Начать тест" становится активной, когда
   X достигает Y.
5. Преподаватель нажимает "Начать тест" — первый вопрос появляется у
   всех студентов одновременно.
6. Студенты отвечают, преподаватель дожидается ответов (по таблице
   результатов или на глаз) и нажимает "Следующий вопрос" — вопрос
   меняется синхронно у всех.
7. После последнего вопроса повторное нажатие "Следующий вопрос"
   завершает тест: студенты видят экран "Тест завершён".
8. Преподаватель нажимает "Обновить результаты" и видит итоговую
   таблицу по каждому студенту.

Если часть студентов не может подключиться (проблемы с Wi-Fi), можно
воспользоваться кнопкой "Начать принудительно" вместо ожидания.

## API

| Метод | Путь                | Назначение                                             |
|-------|---------------------|---------------------------------------------------------|
| GET   | `/`                 | Страница входа студента                                 |
| GET   | `/teacher`          | Панель преподавателя                                    |
| GET   | `/test`             | Страница прохождения теста                               |
| GET   | `/healthz`          | Проверка работоспособности сервиса                       |
| POST  | `/api/upload_test`  | Загрузка GIFT-файла (`multipart/form-data`, поле `file`) |
| GET   | `/api/results`      | Результаты по всем студентам в формате JSON              |
| WS    | `/ws/student`       | WebSocket-канал студента (параметр `name` в query)        |
| WS    | `/ws/teacher`       | WebSocket-канал преподавателя                            |

Сообщения по WebSocket `/ws/teacher` (от клиента к серверу):

```json
{"type": "set_expected", "value": 150}
{"type": "start_test", "force": false}
{"type": "next_question"}
{"type": "reset"}
```

Сообщения по WebSocket `/ws/student` (от клиента к серверу):

```json
{"type": "ping"}
{"type": "answer", "question_id": "…", "value": "…"}
```

## Известные ограничения

- Состояние теста хранится в памяти процесса — перезапуск сервиса
  (`systemctl restart testapp`) сбрасывает всех подключённых студентов,
  загруженный тест и результаты. Для одного сеанса тестирования это
  ожидаемо, но не подходит для многодневных или прерываемых сессий.
- GIFT-парсер поддерживает три типа вопросов (multiple choice,
  true/false, short answer) — сложные конструкции GIFT (matching,
  numeric с диапазонами, embedded answers, обратная связь на ответ)
  не реализованы.
- Ёмкость по числу одновременных студентов ограничена не сервисом
  (FastAPI спокойно держит сотни WebSocket-соединений на одном
  event loop), а радиочастью Wi-Fi точки доступа — см. документацию
  на используемое оборудование.

## Диагностика проблем

**Ошибка `TypeError: unhashable type: 'dict'` при открытии страницы.**
Означает несовместимость версии Starlette с синтаксисом вызова
`TemplateResponse`. В этом проекте уже используется актуальный
синтаксис (`templates.TemplateResponse(request, "name.html", {})`).
Если ошибка всё же возникает, проверьте версию Starlette:

```bash
pip show starlette
```

**Счётчик подключённых студентов считается неверно.**
Проверьте, что сервис запущен одним процессом Uvicorn, а не через
`gunicorn -w N` — при нескольких воркерах состояние расходится между
процессами.

**Не удаётся распарсить GIFT-файл (`ok: false`).**
Проверьте, что вопросы разделены пустой строкой, а в блоке ответов
`{...}` использованы `=` для правильных и `~` для неправильных
вариантов. Сверьтесь с примером в `example.gift`.

**WebSocket рвётся каждые ~60 секунд за Nginx.**
Убедитесь, что в `deploy/nginx_testapp.conf` для `location /ws/`
установлены `proxy_read_timeout` и `proxy_send_timeout` (по умолчанию
уже выставлены в 3600s).
