# control-test

Локальный веб-сервис тестирования студентов без зависимости от Moodle. Преподаватель загружает GIFT-файл и запускает тест, студенты подключаются к Wi-Fi и отвечают через браузер.

## Актуальная версия

Последние изменения находятся в ветке [codex/light-student-ui](https://github.com/AlekseyAnoshko/control-test/tree/codex/light-student-ui), PR [№2](https://github.com/AlekseyAnoshko/control-test/pull/2). Пока изменения не объединены, для функций ниже используйте эту ветку.

## Последнее тестирование — 28 октября 2026

### Проверка на ноутбуке и телефоне

На ноутбуке AAF-Note с Astra Linux 1.8 настроен шлюз с двумя Wi-Fi-адаптерами:

| Компонент | Настройка |
| --- | --- |
| Внешний Wi-Fi / Интернет | Встроенный адаптер `wlp3s0`, шлюз `192.168.0.1` |
| Точка доступа студентов | USB-адаптер `wlx00127b21755b`, драйвер `ath9k_htc` |
| SSID | `control-test` |
| Адрес ноутбука | `10.10.10.1/24` |
| DHCP | `10.10.10.100–10.10.10.250` |
| Шлюз и DNS для студентов | `10.10.10.1` |
| DHCP/DNS-сервис | `control-test-dnsmasq.service` |
| Файрвол и NAT | Таблица nftables `inet control_test` |

Подтверждено выводом команд и проверкой пользователя:
- Конфигурация dnsmasq проходит проверку синтаксиса, сервис активен.
- IPv4 forwarding включён; маршрут от сети студентов проходит через `wlp3s0`.
- Правила ACL, перенаправления DNS на локальный сервер и masquerade загружены; счётчики показывают трафик в обе стороны.
- На телефоне, подключённом к `control-test`, Интернет работает, проверенные сайты нейросетей не открываются.
- Веб-сервер успешно запускается на `10.10.10.1:8000` с одним worker.

Перед применением ACL были убраны правила перехвата Throne/sing-box. Повторное включение перехвата требует отдельной проверки совместимости. Проверка после полной перезагрузки ноутбука и автозапуск всего шлюза пока не подтверждены.

### Программные проверки последней версии

В ходе разработки проверены:
- Вход студента, ожидание, получение вопросов, отправка и подтверждение сохранения ответов.
- Восстановление текущего вопроса и принятого ответа после обновления страницы и переподключения.
- Раскладки для компьютера и телефона без горизонтальной прокрутки и ошибок JavaScript.
- Серверный таймер: автоматическая смена вопросов, отклонение просроченных ответов, завершение после последнего вопроса и отмена таймера при сбросе.
- Установка пользовательского сервиса и ярлыков: три теста установщика и проверка unit-файла.
- Формирование DOCX: 18 серверных тестов прошли на этапе добавления отчёта; проверено оформление документа на 30 участников и повторение заголовка таблицы при переносе.

Проверка отчёта на 30 участников относится к формированию документа, а не к нагрузочному испытанию Wi-Fi. Полный сеанс с таймером и скачиванием DOCX на физическом ноутбуке после последнего обновления пользователем ещё не подтверждён.

## Возможности

- Светлый интерфейс студента: чёрный системный sans-serif текст, крупные элементы, прогресс и состояния соединения. Внешние шрифты и CDN не нужны.
- Загрузка `.gift` или `.txt` в панели преподавателя. Поддерживается подмножество GIFT: варианты ответа, верно/неверно и короткий текстовый ответ.
- Время на вопрос от 1 до 3600 секунд, по умолчанию 60. Устанавливается до запуска теста.
- Общий серверный таймер и автоматическое переключение вопросов. Закрытие панели преподавателя не останавливает тест.
- Ответ должен поступить на сервер до окончания времени. Неотправленный ответ считается неправильным. После последнего вопроса тест завершается.
- Кнопка «Выгрузить отчёт DOCX» доступна после завершения. Название теста берётся из имени загруженного файла, включая расширение `.gift`.
- В отчёте: начало и окончание по времени Иркутска (UTC+08:00), длительность, настройки таймера и результаты участников. Пропуски входят в число неправильных.
- Панель преподавателя показывает адрес входа студентов и локальный QR-код Wi-Fi с увеличением.

## Обновление на проверенном ноутбуке

Перед перезапуском скачайте нужный отчёт: ответы хранятся в памяти.

```bash
(
set -e
cd ~/git/control-test-gateway
git fetch github codex/light-student-ui
git switch --detach FETCH_HEAD
./.venv/bin/python -m pip install -r requirements.txt
systemctl --user restart control-test-web.service
)
```

После обновления нажмите Ctrl+F5 в браузере. Команды предполагают уже настроенный remote `github`, окружение `.venv` и установленный сервис.

## Запуск и остановка

Требуются Python 3.10+, зависимости проекта и активная точка доступа с адресом `10.10.10.1`.

Первичная установка окружения и кнопок — от пользователя рабочего стола, без sudo:

```bash
cd ~/git/control-test-gateway
python3 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
python3 deploy/install_desktop.py
```

Установщик создаёт пользовательский `control-test-web.service` и ярлыки в фактической папке рабочего стола:
- «Запустить тестирование» запускает сервер и открывает панель преподавателя.
- «Остановить тестирование» останавливает веб-сервер.

Сервис продолжает работать после закрытия терминала. Автоматический запуск при входе не включён; остановка веб-сервера не отключает Wi-Fi и ACL.

| Страница | Адрес |
| --- | --- |
| Вход студентов | http://10.10.10.1:8000/ |
| Панель преподавателя | http://10.10.10.1:8000/teacher |
| Проверка сервера | http://10.10.10.1:8000/healthz |

Управление и журнал:

```bash
systemctl --user start control-test-web.service
systemctl --user stop control-test-web.service
systemctl --user status control-test-web.service --no-pager
journalctl --user -u control-test-web.service -n 40 --no-pager
```

Для ручного запуска:

```bash
./.venv/bin/python -m uvicorn app.main:app --host 10.10.10.1 --port 8000 --workers 1
```

QR-код с паролем хранится только локально в `app/static/control-test-wifi-qr.png`. Пароль и изображение с ним не включаются в репозиторий.

## Сеть и диагностика

Инструкция по настройке шлюза: [deploy/GATEWAY.md](https://github.com/AlekseyAnoshko/control-test/blob/codex/light-student-ui/deploy/GATEWAY.md). Имена адаптеров и пути в командах относятся к проверенному ноутбуку.

NetworkManager использует профиль `control-test-hotspot` с `ipv4.method manual`. DHCP/DNS обслуживает отдельный dnsmasq; параллельный DHCP NetworkManager в режиме `shared`, системный dnsmasq и DHCP VMware не должны конфликтовать с ним.

```bash
sudo systemctl is-active control-test-dnsmasq.service
sudo sysctl net.ipv4.ip_forward
ip -4 route get 1.1.1.1 from 10.10.10.100 iif wlx00127b21755b
sudo /usr/sbin/nft list table inet control_test
sudo journalctl -u control-test-dnsmasq.service -n 40 --no-pager
sudo /sbin/iw dev wlx00127b21755b station dump
```

Для проверки именно сети студентов на телефоне отключите мобильные данные и VPN.

## Ограничения

- Состояние хранится в памяти одного процесса. Запускайте один worker. Сброс, загрузка другого теста и перезапуск удаляют данные; скачивайте отчёт заранее.
- Отключившиеся участники сохраняются в результатах текущего запуска, но не учитываются как подключённые.
- Подтверждение личности и разграничение доступа преподавателя и студента пока не реализованы. Сервис предназначен для локальной сети.
- DNS-фильтр не гарантирует блокировку всех AI-сервисов и способов обхода: DoH, VPN, прямые IP и мобильный Интернет требуют отдельного контроля.
- Нагрузочные испытания на 30 или 150 реальных устройствах не проводились.
- `android-client/ExamNetworkGuard.kt` — заготовка, а не готовое приложение допуска к тестированию.
