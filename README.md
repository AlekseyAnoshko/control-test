# control-test

Локальный веб-сервис тестирования студентов без зависимости от Moodle. Преподаватель загружает GIFT-файл и запускает тест, студенты подключаются к Wi-Fi и отвечают через браузер.

## Актуальная версия

Актуальный код находится в ветке [master](https://github.com/AlekseyAnoshko/control-test/tree/master). Изменения интерфейса, шлюза, таймера, DOCX-отчёта и контроля Wi-Fi включены в основную ветку.

### DNS и адрес тестирования

Локальная запись `host-record=test.int,10.10.10.1` обслуживается dnsmasq.
Новый адрес указан в панели преподавателя и окне увеличения QR.
Прямой адрес `http://10.10.10.1:8000/` остаётся доступен.
QR предназначен для подключения к Wi-Fi; смена имени сайта не меняет пароль сети.
Имя `test.int` настроено локально и требует DNS ноутбука; публичная регистрация
домена не выполнялась. Порт веб-сервиса остаётся `8000`.

### Совместная работа с Hiddify

Конфликт был связан с перехватом TCP на локальный прокси-порт Hiddify
и маршрутизацией через `tun0`: прежний firewall разрешал пересылку только
через `wlp3s0`. В таблицу `inet control_test` добавлены разрешения для
перенаправленного TCP-трафика студентов и пересылки через `tun0`.
После применения правил пользователь подтвердил доступ в Интернет с телефона.

На ноутбуке установлены:
- `/etc/sysctl.d/90-control-test-forward.conf`: `net.ipv4.ip_forward=1`.
- `/etc/control-test/gateway.nft`: постоянная конфигурация firewall,
  включая набор портов `vpn_proxy_ports`.
- `/usr/local/sbin/control-test-firewall`: загрузчик таблицы и обновление
  набора по TCP redirect-правилам sing-box.
- `control-test-firewall.service` и `control-test-firewall.timer`:
  загрузка после старта системы и проверка порта каждые 3 секунды.

Эти служба, таймер и вспомогательный скрипт созданы при настройке конкретного
ноутбука; обычные установщики репозитория пока не воспроизводят их автоматически.
Таблица VPN `inet sing-box` сохраняется. Имя TUN в текущем firewall — `tun0`;
автоматически обновляется порт, а не имя VPN-интерфейса.
Полная проверка после перезагрузки ноутбука ещё не выполнена.

### Страница запрета нейросетей

Установка `deploy/install_ai_warning.py` на ноутбуке завершилась успешно:
синтаксис dnsmasq проверен, настроены **33 домена и их поддомены**.
Список объединяет `deploy/blocked-ai-domains.txt` и локальные DNS-запреты,
включая DeepSeek и Kimi/Moonshot.

Для запрещённых доменов локальный DNS возвращает `10.10.10.1`.
HTTP-порт 80 перенаправляется на локальный веб-сервис 8000; по заголовку Host
сервис показывает текст **«Использование нейросетей на время тестирования
запрещено»** и ссылку для возврата к тесту. Прямой адрес предупреждения —
`http://test.int:8000/ai-blocked`.
HTTPS/HSTS сохраняет проверку сертификата исходного домена, поэтому при таком
обращении возможна ошибка подключения вместо страницы предупреждения.
Показ предупреждения на телефоне после этой установки пока не подтверждён.

Установщик сохраняет резервные копии DNS/firewall, проверяет конфигурации
до применения и записывает объединённый список в
`/etc/control-test/ai-warning-domains.txt`. Веб-сервис читает этот список
при запуске; после его изменения нужен перезапуск веб-сервиса.

### Последние исправления тестирования

- У каждого студента свой серверный таймер; после сохранения ответа сразу
  открывается следующий вопрос. При истечении времени вопрос пропускается
  и считается неправильным.
- Панель преподавателя переподключается после перезапуска сервера и обновляет
  результаты автоматически; данные прошлого сеанса очищаются при новом тесте.
- Исправлен разбор положительных весов GIFT, дробных процентов, нескольких
  допустимых коротких ответов и экранированных символов. Добавлены числовые
  ответы с допуском и задания на соответствие со списками выбора.
- Приложенный банк AL-1804 содержит 68 вопросов: прежний загрузчик пропускал
  три числовых и показывал 65. Серверный прогон исправленной версии сохранил
  68 из 68 ответов. Причина девяти пропусков в прежнем результате 56/65
  отдельно не установлена.
- После добавления страницы запрета прошли 44 серверных теста; это не
  нагрузочное испытание Wi-Fi и не подтверждение работы на 30 телефонах.

## Возможности

- Светлый интерфейс студента: чёрный системный sans-serif текст, крупные элементы, прогресс и состояния соединения. Внешние шрифты и CDN не нужны.
- Загрузка `.gift` или `.txt` в панели преподавателя. Поддерживаются одиночный и множественный выбор, верно/неверно, короткий и числовой ответ, соответствия; подробности ниже.
- Время на вопрос от 1 до 3600 секунд, по умолчанию 60. Устанавливается до запуска теста.
- Индивидуальный серверный таймер для каждого студента и немедленный переход после ответа. Закрытие панели преподавателя не останавливает тест.
- Ответ должен поступить на сервер до окончания времени. Неотправленный ответ считается неправильным. После последнего вопроса тест завершается.
- Кнопка «Выгрузить отчёт DOCX» доступна после завершения. Название теста берётся из имени загруженного файла, включая расширение `.gift`.
- В отчёте: начало и окончание по времени Иркутска (UTC+08:00), длительность, настройки таймера и результаты участников. Пропуски входят в число неправильных.
- Панель преподавателя показывает адрес входа студентов и локальный QR-код Wi-Fi с увеличением.
- Страница `/students`: имя студента, IP, MAC, состояние Wi-Fi и оставшееся время запрета входа.
- При разрыве Wi-Fi зарегистрированное устройство теряет доступ к сайту на 10 минут. Повторные попытки не продлевают запрет; закрытие вкладки его не вызывает.
- При запуске веб-сервиса, загрузке нового теста, начале и сбросе тестирования очищаются регистрации и запреты прошлого сеанса. Подключённые участники текущего ожидания сохраняются; отключённые старые участники удаляются.

## Обновление на проверенном ноутбуке

Перед перезапуском скачайте нужный отчёт: ответы хранятся в памяти.

```bash
(
set -e
cd ~/git/control-test-gateway
git fetch github master
git switch --detach FETCH_HEAD
./.venv/bin/python -m pip install -r requirements.txt
systemctl --user restart control-test-web.service
)
```

После обновления нажмите Ctrl+F5 в браузере. Команды предполагают уже настроенный remote `github`, окружение `.venv` и установленный сервис.

## Запуск и остановка

Требуются Python 3.10+, зависимости проекта и активная точка доступа с адресом `10.10.10.1`.

Первичная установка окружения и кнопок — от пользователя рабочего стола, без sudo:

```bash
cd ~/git/control-test-gateway
python3 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
python3 deploy/install_desktop.py
```

Установщик создаёт пользовательский `control-test-web.service` и ярлыки в фактической папке рабочего стола:
- «Запустить тестирование» запускает сервер и открывает панель преподавателя.
- «Остановить тестирование» останавливает веб-сервер.

Сервис продолжает работать после закрытия терминала. Автоматический запуск при входе не включён; остановка веб-сервера не отключает Wi-Fi и ACL.

| Страница | Адрес |
| --- | --- |
| Вход студентов | http://test.int:8000/ |
| Панель преподавателя | http://test.int:8000/teacher |
| Подключения студентов | http://test.int:8000/students |
| Проверка сервера | http://test.int:8000/healthz |

Управление и журнал:

```bash
systemctl --user start control-test-web.service
systemctl --user stop control-test-web.service
systemctl --user status control-test-web.service --no-pager
journalctl --user -u control-test-web.service -n 40 --no-pager
```

Для ручного запуска:

```bash
./.venv/bin/python -m uvicorn app.main:app --host 10.10.10.1 --port 8000 --workers 1
```

QR-код с паролем хранится только локально в `app/static/control-test-wifi-qr.png`. Пароль и изображение с ним не включаются в репозиторий.

## Сеть и диагностика

Инструкция по настройке шлюза: [deploy/GATEWAY.md](https://github.com/AlekseyAnoshko/control-test/blob/master/deploy/GATEWAY.md). Имена адаптеров и пути в командах относятся к проверенному ноутбуку.

NetworkManager использует профиль `control-test-hotspot` с `ipv4.method manual`. DHCP/DNS обслуживает отдельный dnsmasq; параллельный DHCP NetworkManager в режиме `shared`, системный dnsmasq и DHCP VMware не должны конфликтовать с ним.

```bash
sudo systemctl is-active control-test-dnsmasq.service
sudo /usr/sbin/sysctl net.ipv4.ip_forward
ip -4 route get 1.1.1.1 from 10.10.10.100 iif wlx001d43501e71
sudo /usr/sbin/nft list table inet control_test
sudo journalctl -u control-test-dnsmasq.service -n 40 --no-pager
sudo /usr/sbin/iw dev wlx001d43501e71 station dump
```

Для проверки именно сети студентов на телефоне отключите мобильные данные и VPN.

## Ограничения

- Вопросы и ответы текущего теста хранятся в памяти одного процесса. История MAC относится к текущему сеансу. Запускайте один worker. Сброс, загрузка другого теста и перезапуск удаляют данные; скачивайте отчёт заранее.
- Отключившиеся участники сохраняются в результатах текущего запуска, но не учитываются как подключённые.
- Подтверждение личности и разграничение доступа преподавателя и студента пока не реализованы. Сервис предназначен для локальной сети.
- DNS-фильтр не гарантирует блокировку всех AI-сервисов и способов обхода: DoH, VPN, прямые IP и мобильный Интернет требуют отдельного контроля.
- Нагрузочные испытания на 30 или 150 реальных устройствах не проводились.
- `android-client/ExamNetworkGuard.kt` — заготовка, а не готовое приложение допуска к тестированию.

## Подключения студентов и запрет входа после разрыва Wi-Fi

Страница преподавателя `/students` показывает устройства USB-точки доступа,
имя после входа в тест, IP, MAC, состояние Wi-Fi и оставшееся время запрета.
Ссылка есть в панели преподавателя. После реального разрыва Wi-Fi доступ
зарегистрированного устройства к сайту закрывается на 600 секунд с момента
разрыва; Wi-Fi и Интернет продолжают работать. Попытки входа не продлевают
срок. Обновление страницы, закрытие вкладки и разрыв WebSocket не являются
разрывом Wi-Fi. При запрете HTTP возвращает 403, WebSocket закрывается с 4403.

Браузер не сообщает MAC. Отдельная системная служба читает события AP из
wpa_supplicant, сверяет список станций через `iw` и сопоставляет их с DHCP leases.
Она не меняет NetworkManager, DNS, firewall и настройки точки доступа.
Веб-сервис остаётся без прав root. Новых Python-зависимостей нет.

Установка на AAF-Note (точка `control-test` должна быть включена; сначала
подключите телефон, чтобы существовал файл DHCP leases):

```bash
cd ~/git/control-test-gateway
./.venv/bin/python -m pip install -r requirements.txt
sudo python3 deploy/install_wifi_monitor.py --interface wlx001d43501e71
# После выгрузки нужных результатов: перезапуск очищает текущий тест.
systemctl --user restart control-test-web.service
```

Установщик сначала проверяет доступ к событиям точки и `iw`, затем устанавливает
`control-test-wifi.service` с автозапуском. Он не отключает Wi-Fi и не перезапускает
DNS. Параметры по умолчанию: интерфейс `wlx00127b21755b`, управляющий сокет
`/run/wpa_supplicant/wlx00127b21755b`, leases
`/var/lib/misc/control-test-dnsmasq.leases`. Другой путь задаётся через
`--lease-file`, другой адаптер — через `--interface`.

Проверка: откройте `http://10.10.10.1:8000/students` на ноутбуке и дождитесь
«Контроль Wi-Fi работает». На телефоне откройте сайт и войдите под своим именем.
Обновление/закрытие вкладки не должно блокировать доступ. Выключите Wi-Fi на
телефоне, подождите 3–5 секунд и включите обратно: Интернет доступен, сайт
показывает запрет, в списке преподавателя идёт обратный отсчёт. Спустя 10 минут
от отключения повторный вход разрешён. Проверьте также быстрый обрыв с
переподключением. Работа функционала на телефоне подтверждена пользователем 29 октября 2026 года. Этот сценарий следует повторять после изменений сетевой конфигурации; автоматические тесты не заменяют проверку оборудования.

Сведения об устройствах/интервалах сохраняются в
`/var/lib/control-test-wifi/state.json` (root), регистрации/имена — в
`~/.local/state/control-test/wifi.sqlite3` пользователя веб-сервиса. Перезапуск
веб-сервиса, загрузка нового теста, начало и сброс теста очищают регистрации и запреты прошлого сеанса. Очистка браузера во время теста запрет не снимает. Отключённые устройства прошлых сеансов скрыты на `/students`, реальные подключения Wi-Fi остаются видны.
Статус публикуется в `/run/control-test-wifi/status.json`; устаревший статус
отображается как ошибка контроля. Новые отключения при отказе мониторинга
не выдумываются и не наказываются. Известные интервалы сохраняются, но запрет
применяется только при свежем сопоставлении IP и MAC, чтобы не наказать чужое
устройство по устаревшему адресу.
Отключение самой точки доступа не наказывается как отключение студента.
Разрыв фиксируется, когда AP обнаружит исчезновение клиента; при внезапной
потере радиосвязи это может произойти не сразу. Стандартные события описаны в
[документации wpa_supplicant](https://w1.fi/wpa_supplicant/devel/ctrl_iface_page.html).

Это контроль обычных DHCP-клиентов, а не защита от подмены устройства: смена
MAC/статического IP может обойти сопоставление. Включённый для сети случайный
MAC телефона используется как есть; для стабильной регистрации не меняйте его
во время теста. При неисправности USB/AP возможна потеря достоверного наблюдения;
смотрите индикатор контроля, не считайте это доказательством нарушения студента.

Диагностика и отключение контроля (Wi-Fi останется работать):

```bash
sudo systemctl status control-test-wifi.service --no-pager
sudo journalctl -u control-test-wifi.service -n 60 --no-pager
sudo systemctl disable --now control-test-wifi.service
```

Остановка монитора приостанавливает контроль доступа, но сохраняет интервалы
в истории. После восстановления свежих данных ещё не истёкший запрет применяется снова.

Панель преподавателя автоматически восстанавливает WebSocket после перезапуска сервера и обновляет результаты без ручной перезагрузки страницы.

## Индивидуальное прохождение

После сохранения ответа студент сразу получает следующий вопрос. Каждый вопрос
имеет собственный серверный таймер для каждого участника. Если время вышло,
вопрос считается пропущенным (неправильным), и открывается следующий.
Обновление страницы и отключение не останавливают и не продлевают таймер.
Закончивший студент видит завершение; остальные продолжают. Общий тест и
выгрузка DOCX становятся завершёнными, когда закончили все участники.
В панели преподавателя отображается число завершивших; общей кнопки перехода
к следующему вопросу больше нет.

## Форматы GIFT

Поддерживаются одиночный выбор, множественный выбор с положительными весами
(`~%50%`, `~%33.33333%`), короткие ответы с несколькими допустимыми вариантами,
числовые ответы (`{#3}`, `{#3:0.1}`), верно/неверно и соответствия (`=левая часть -> правая часть`).
Для множественного выбора требуется весь правильный набор без лишних вариантов;
частичные баллы Moodle не начисляются. У соответствий каждый пункт имеет свой
список вариантов. Экранированные символы GIFT в путях и шаблонах сохраняются.
Вопросы с вариантами, но без распознанного правильного ответа, вызывают ошибку
загрузки вместо появления неразрешимого вопроса.

## Страница запрета нейросетей

`http://test.int:8000/ai-blocked` показывает сообщение
«Использование нейросетей на время тестирования запрещено» и ссылку на тест.
Для включения после обновления кода выполните
`sudo python3 deploy/install_ai_warning.py`, затем перезапустите пользовательский
`control-test-web.service` после сохранения текущих результатов.
Установщик сохраняет резервные копии DNS и firewall, проверяет конфигурации,
направляет домены из чёрного списка на 10.10.10.1 и HTTP-порт 80 на веб-сервис 8000.
Правила сохраняются в `/etc/control-test/gateway.nft`; на настроенном ноутбуке
их восстанавливает `control-test-firewall.timer`.

Автоматическая страница работает при обычном HTTP и DNS ноутбука. HTTPS/HSTS
не позволяет подменять сайт без сертификата исходного домена: браузер покажет
ошибку подключения, а не нашу страницу. DoH, сторонний VPN и мобильный интернет
могут обходить DNS-фильтрацию. Чёрный список не является полным запретом всех
нейросетей. Переустановка шлюза может перегенерировать конфигурацию — после неё
повторно запустите установщик страницы.
