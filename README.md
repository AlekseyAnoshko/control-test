# control-test

Самостоятельный локальный веб-сервис тестирования студентов. Преподаватель загружает тест в поддерживаемом подмножестве формата GIFT, задаёт число участников и управляет последовательной выдачей вопросов; студенты подключаются по Wi-Fi и отвечают через браузер. GIFT — формат входных данных, а не программная зависимость от какой-либо системы обучения.

## Что реализовано

- Страница входа студента `/`, панель преподавателя `/teacher`, страница вопросов `/test`.
- Загрузка файла с вопросами через `/api/upload_test`; поддерживаются варианты ответа, верно/неверно и короткий текстовый ответ (не весь синтаксис GIFT).
- WebSocket `/ws/student` и `/ws/teacher`: число текущих подключений, запуск теста преподавателем, синхронная выдача следующего вопроса и приём ответов.
- Получение результатов через `/api/results`. Состояние, ответы и список подключённых хранятся в памяти **одного** процесса Uvicorn; при перезапуске они теряются, а после отключения студента его запись удаляется из текущего списка.

В текущей версии имя передаётся клиентом, а маршруты и WebSocket не требуют подтверждённой личности студента или преподавателя. Счётчик подключённых — не гарантированная идентификация устройств. Красно-зелёная история статуса каждого студента, постоянный список группы и привязка по MAC пока не реализованы. Не используйте текущую версию для значимых экзаменов без дополнительных мер и проверки безопасности.

## Два варианта сети

| Сценарий | Роль ноутбука | Где находятся правила сети |
| --- | --- | --- |
| Небольшая аудитория, ориентир до 30 студентов | Локальный веб-сервер и маршрутизатор с Wi-Fi-адаптером в режиме точки доступа | DHCP/DNS и файрвол на ноутбуке; примеры конфигурации в `deploy/` |
| Большая аудитория, проектный ориентир до 150 студентов | Локальный веб-сервер, подключённый к инфраструктуре по Ethernet | DHCP/DNS и правила доступа на шлюзе/оборудовании Ruckus; конкретные возможности зависят от модели, прошивки и режима работы |

Числа 30 и 150 — цели развёртывания, а не подтверждённые нагрузочными испытаниями пределы. Наличие файлов конфигурации не подтверждает, что конкретный Wi-Fi-адаптер поддерживает AP-режим или что правила файрвола уже действуют. Для режима 30 клиентов отдельно проверьте драйвер и `iw phy ... info`: если `AP` отсутствует, этот адаптер не подходит для штатного запуска хот-спота. Для режима 150 клиентов проверьте, что фактический шлюз, DNS и политики заданы на используемой конфигурации Ruckus; точка доступа в режиме моста сама по себе не становится маршрутизатором.

## Политика сетевого доступа: проект

Планируемая политика для обоих вариантов — запрет исходящих соединений по умолчанию, разрешён только локальный сервис тестирования, необходимые DHCP/DNS и специально проверенные внешние назначения, если без них нельзя провести тест. Для варианта с ноутбуком правила пересылки должны применяться на ноутбуке, если именно он указан клиентам как шлюз. Для варианта с оборудованием Ruckus ограничения применяются на фактическом шлюзе. Одной выдачи адреса DNS-сервера недостаточно для фильтрации всего HTTP/HTTPS-трафика: DNS и шлюз — разные роли.

Тестирование можно проводить без обязательной зависимости от внешних сервисов. Отдельно следует проверить IPv4/IPv6, обход через внешние DNS/DoH и прямые IP-соединения. Ни правила Wi-Fi, ни DNS не отключают сотовую сеть личного смартфона и не исключают параллельный доступ через неё. Реализованного универсального белого списка в репозитории пока нет.

## Android-клиент: статус заготовки

`android-client/ExamNetworkGuard.kt` — отдельный Kotlin-класс, который проверяет признак `TRANSPORT_VPN` у активной сети приложения и получает уведомления об изменении сетевого состояния. Это **не собираемое Android-приложение**: в репозитории нет Android-проекта, манифеста или интерфейса тестирования. `VPN_NOT_DETECTED` означает только, что признак не обнаружен проверкой; это не гарантия отсутствия VPN для всего трафика телефона.

Планируемая локальная проверка: Android-приложение не открывает тест при `VPN_ACTIVE` или `NETWORK_UNKNOWN` и повторяет проверку при изменении состояния сети. Серверу потребуется собственная проверка допуска к студенческому WebSocket и защита остальных маршрутов, чтобы нельзя было войти напрямую через браузер. Простому сообщению клиента «VPN не обнаружен» нельзя доверять как доказательству состояния устройства: проверка на личном телефоне остаётся обходной. Эти серверные ограничения **пока не реализованы**. В проекте нет зависимости от сервисов Google для допуска к тестированию.

## Локальный запуск веб-сервиса

Требования: Python 3.10+ и пакеты из `requirements.txt`. На ноутбуке с Astra Linux или другой совместимой системой:

```bash
cd ~/git/control-test
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Преподаватель открывает `http://<IP-ноутбука>:8000/teacher`, студент — `http://<IP-ноутбука>:8000/`. Проверка процесса: `curl http://127.0.0.1:8000/healthz`. Не публикуйте этот неаутентифицированный сервис в Интернете. Для развёртывания с Nginx и systemd имеются примеры `deploy/nginx_testapp.conf` и `deploy/testapp.service`; перед использованием проверьте локальные пути и параметры сети.

Сценарий работы: преподаватель загружает тест, задаёт ожидаемое число участников, студенты открывают страницу входа и вводят имена, преподаватель запускает тест и переключает вопросы, после чего запрашивает результаты. Пример входного файла — `example.gift`.

## Файлы

- `app/main.py` — FastAPI, упрощённый GIFT-парсер, WebSocket и состояние теста.
- `app/templates/` — страницы входа, преподавателя и вопросов.
- `deploy/hostapd.conf`, `deploy/dnsmasq-hotspot.conf`, `deploy/start_hotspot.sh`, `deploy/wifi_adapter.sh` — примеры настройки локального хот-спота; перед применением проверьте интерфейсы, подсети и параметры доступа.
- `deploy/nginx_testapp.conf`, `deploy/testapp.service` — примеры запуска сервиса.
- `android-client/ExamNetworkGuard.kt` — заготовка проверки состояния сети на Android.

## Ограничения

- Запускать сервер одним процессом: состояние хранится в оперативной памяти, а не в общей БД. Перезапуск обнуляет тест и результаты.
- Текущий `/ws/student` принимает указанное клиентом имя без проверки Android-приложения; прямой вход из браузера пока возможен. Страница преподавателя и управление тестом также нуждаются в авторизации.
- MAC-адрес Wi-Fi можно рассматривать как дополнительное сетевое ограничение, но не как единственное доказательство личности: мобильные ОС используют частные MAC-адреса, а веб-сервер обычно не получает MAC через HTTP.
- Поддерживается ограниченное подмножество GIFT; перед экзаменом проверяйте импорт и оценивание конкретных файлов.
- Требования к доступности для 30/150 клиентов и белому списку являются целями разработки до практической проверки в обеих схемах сети.
